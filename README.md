# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Система поддерживает подключение реле отопления определенного типа.
- Система управляет реле отопления через внешний облачный сервис.

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система поддерживает подключение датчиков определенного типа.
- Система получает данные о температуре с датчиков, установленных в домах через внешний облачный сервис.

### 2. Анализ архитектуры монолитного приложения

Бекенд приложения использует язык Go, базу данных Postgres как хранилище данных, управляет датчиками и реле отопления через внешний облачный сервис по REST API.
Фронтенд приложения использует React, взаимодействует с бекендом по REST API

### 3. Определение доменов и границы контекстов
Выделены домены
1. Мониторинг 
Сбор, хранение, предоставление данных с датчиков.
Контекст мониторинга
	Entities: датчик
	Value Objects: значение, получаемое с датчика с привязкой по времени
В текущей реализации выделен поддомен мониторинга температуры
	Сбор, хранение, предоставление данных о температуре с датчиков.
	Контекст мониторинга температуры
	Entities: датчик температуры
	Value Objects: значение температуры
2. Управление устройствами
Контекст управления устройствами:
	Entities: устройство (реле и другие)
	Value Objects: статус (состояние) устройства
В текущей реализации выделен поддомен управления отоплением
	Включение и выключение отопления по команде пользователя. Хранение данных о текущем состоянии.
	Контекст управления отоплением:
	Entities: устройство управления отоплением (реле)
	Value Objects: состояние управления отоплением (вкл/выкл)
3. Пользователи
Аутентификация и авторизация пользователей, связанность пользователя с их устройствами/домом.
	Контекст пользователей
	Entities: пользователь
	Value Objects: аутентификационные данные


### **4. Проблемы монолитного решения**

- Ограниченная функциональность по управлению отоплением со стороны пользователя: только вкл/выкл, нет возможности задать
расписание, поддержание температуры.
- Невозможность самостоятельного подключения к системе со стороны пользователя.
- Ограниченная возможность масштабирования монолитного приложения.
